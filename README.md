# Стальной охотник — прототип режима «королевская битва» с танками

Один режим: «Стальной охотник». Игрок выживает на большой карте, собирает добычу,
улучшает машину прямо в бою, зона постепенно сжимается, побеждает последний выживший.

Текущий этап: **0 — подготовка** (анкета требований, инструменты, пайплайн моделей).

## Что уже сделано

| Что | Где |
|---|---|
| Анкета из 60 вопросов о игре (10 блоков) с сохранением, экспортом в файл и копированием | `site/` |
| Установка Blender (headless, Python-модуль `bpy` 4.5 LTS) с заглушками для X11/GL | `tools/install_blender.sh`, `tools/make_gl_stubs.py` |
| Обёртка запуска Blender-скриптов | `tools/blender.sh` |
| Демо-модель танка: сборка → превью-рендер (Cycles, CPU) → экспорт GLB | `tools/tank_demo.py` |
| Результат демо: `assets/generated/tank_demo.glb`, `tank_demo_preview.png`, `tank_demo.blend` | `assets/generated/` |

## Анкета

```bash
cd site && python3 -m http.server 8000
```
Открыть `http://localhost:8000` → ответить → «Итог» → «Скопировать ответы» и прислать текст в чат.
Ответы дублируются в localStorage браузера, кнопка «Скачать .txt» сохраняет их файлом.

## Blender (модели техники)

В песочнице Blender ставится как Python-модуль `bpy` в `~/.local/bpy-venv` (вне репозитория,
~1.5 ГБ, поэтому в git не попадает). Системных `libGL`/`libX11` здесь нет — скрипт
`tools/make_gl_stubs.py` генерирует shim `libstubs.so` и подкладывает его под имена
недостающих библиотек. Для headless-задач (моделирование, рендер Cycles на CPU, экспорт
GLB/FBX) этого достаточно: к GL-контексту Blender не обращается.

```bash
tools/install_blender.sh            # один раз: venv + bpy + заглушки + самопроверка
tools/blender.sh tools/tank_demo.py # сборка танка, рендер, экспорт GLB
tools/blender.sh -c "import bpy; print(bpy.app.version_string)"
```

Если Blender установлен на твоём ПК (Windows/Linux), тот же скрипт запускается штатно:

```bash
blender --background --python tools/tank_demo.py
```

Важно: на машине без GPU включать только `CYCLES` в режиме `CPU` (или EEVEE — он требует GL).
OptiX/CUDA здесь недоступны.

## Структура

```
site/                    анкета (статические файлы, без сборки)
tools/                   установка Blender, заглушки, запуск, генерация моделей
assets/generated/        результаты генерации (модели, превью)
```

## План (уточняется ответами анкеты)

1. **Этап 0.** Анкета, инструменты, пайплайн моделей. ← мы здесь
2. **Этап 1.** Прототип боя: танк едет, стреляет, боты-мародёры, зона, лут.
3. **Этап 2.** Машины, умения, прокачка в бою, HUD.
4. **Этап 3.** Карта, визуал, звук, награды, меню/ангар.
5. **Этап 4.** Онлайн, прогрессия, задачи.

Движок и конкретика определяются после ответов на блоки A–J анкеты.
